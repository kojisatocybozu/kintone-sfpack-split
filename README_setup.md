# kintone SFAパック カスタマイズ導入手順

> 対象：**SFAパック標準アプリ群をkintoneに追加した直後の環境**。本書は、追加フィールド・明細管理アプリ・JavaScriptカスタマイズを順番に導入するための手順です。既存環境への更新方法も後半に記載します。
>
> 根拠：リポジトリ `kintone-sfpack-split-main`（提供ZIP、コミット `48c5937`）の実ファイルを確認して作成。PoC由来のため、まず検証環境で実施してください。

## 1. 導入の前提と全体の流れ

SFAパックの標準アプリ（案件管理、顧客管理、担当者管理など）をkintoneへ追加済みであることを前提とします。**標準アプリの追加だけでは、今回のカスタマイズに必要なテーブルや管理フィールドは揃いません。**

導入は以下の順番で進めます。途中でJavaScriptカスタマイズを登録する必要はありません。

1. 対象アプリID・権限・配布物を確認する
2. 案件管理の全フィールドを統合スクリプトで追加する
3. 案件管理のフォーム配置を調整して設定を反映する
4. 明細管理アプリを新規作成する
5. 顧客管理に事業所階層・現場NGフィールドを追加する
6. 環境別設定JavaScriptを準備する
7. 案件管理・顧客管理へJavaScriptを登録する
8. 動作を確認する

**注意：** 以下のConsole用スクリプトは、一度限りの**アプリ構成変更用**です。kintoneの「JavaScript / CSSでカスタマイズ」に登録するファイルではありません。実行時にはアプリ管理権限が必要です。

## 2. 導入前の準備

### 2.1 アプリとIDを控える

| アプリ | 用途 | アプリID（記入） |
|---|---|---|
| 案件管理 | 主なカスタマイズ対象 | |
| 顧客管理 | 事業所階層・現場NGのカスタマイズ対象 | |
| 担当者管理 | 案件管理の担当者選択先 | |
| 明細管理 | **第4章で新規作成** | 作成後に記入 |

活動履歴など標準SFAパック側の関連アプリも、必要に応じて標準設定を確認してください。ルックアップ・アクセス権・参照関係が正しいことを確認します。

### 2.2 必要な配布ファイル

| ファイル | 使い方 |
|---|---|
| `scripts/add-deal-fields.js` | 案件管理の基本テーブル・金額日付24項目・コピー履歴2項目・担当者名5項目を一括追加（Consoleで実行） |
| `scripts/create-proposal-detail-app.js` | 明細管理アプリを新規作成（Consoleで実行） |
| `scripts/add-customer-hierarchy-fields.js` | 顧客管理の階層・現場NG項目を追加（Consoleで実行） |
| `src/config/production.js` | **ひな形**。環境のアプリIDに合わせて編集してから登録 |
| `dist-prod/sfpack-customization.js` | 案件管理に登録するビルド済みJavaScript |
| `dist-prod/customer-customization.js` | 顧客管理に登録するビルド済みJavaScript |

**提供ZIPには `dist-prod/` のビルド成果物が含まれていません。** 導入前に開発担当者から2つのビルド済みJSを入手してください。開発担当者が生成するコマンドは `pnpm run build:prod` です。導入担当者にNode.js・pnpmは不要です。

### 2.3 作業上の注意

- まずテスト用のSFAパック環境で実施し、既存フォーム設定・JavaScript・アクセス権を控えます。
- 各スクリプトは**対象アプリの画面**でF12 → Consoleを開き、ファイル内容を確認して貼り付け・実行します。確認ダイアログの対象アプリIDを必ず確認します。
- 実行エラーが出た場合は次のスクリプトに進まず、Consoleログとフィールド一覧を確認します。
- アプリの設定変更後は「アプリを更新」で反映します。ただしスクリプトごとに反映動作が異なるため、各章の注意に従ってください。

## 3. 案件管理：フィールドを一括追加する

**SFAパックの標準「案件管理」アプリを追加した後**、次の手順で必要なフィールドを一括追加します。

1. 検証環境の**案件管理アプリ**を開き、管理者権限とアプリIDを確認します。
2. ブラウザーの開発者ツール（F12）→ Console に `scripts/add-deal-fields.js` の全文を貼り付け、実行します。
3. 確認ダイアログに従い、基本テーブル、金額・日付項目、コピー履歴・担当者名の追加を承認します。
4. Consoleの**「全フィールド追加・確認が完了しました」**というメッセージを確認します。エラーの場合は途中まで追加されたプレビュー設定を確認し、原因を解消してから再実行してください。
5. 案件管理アプリのフォーム編集画面で、以下のフィールドを確認し、必要に応じて配置を調整します。

| 対象 | 作成するフィールド |
|---|---|
| 担当者テーブル | `担当者テーブル`：`担当者`、`担当者No_` |
| コピー元の明細テーブル | `明細テーブル`：`提案商品_0`、`確度_0`、`商談フェーズ_0`、`見込み金額_0`、`受注金額_0`、`受注予定日_0`、`受注日_0` |
| 担当者別明細 | `担当者別明細01`～`05`：各テーブルに提案商品・確度・商談フェーズ・見込み金額・受注金額・受注予定日・受注日の7列 |
| 担当者No管理 | `明細担当者No_01`～`05` |
| 担当者名 | `担当者名01`～`05`（文字列（1行）、テーブル外） |
| コピー履歴 | `最終明細コピー日時`（日時）、`最終明細コピー実行者`（ユーザー選択） |

**フォーム配置について：** スクリプトは基本テーブルと担当者No管理フィールドのレイアウトを設定しますが、金額・日付列、担当者名、コピー履歴フィールドの配置は手動で調整してください。担当者名01～05は対応する担当者別明細の近くに配置すると分かりやすくなります。

続いて、フォーム編集画面に**スペース**を手動配置し、要素IDを設定します。

| 要素ID | 用途 |
|---|---|
| `selPerson` | 担当者選択ボタン |
| `copyProposalDetails` | 共通明細のコピー、明細管理へのレコード化ボタン（共用） |

**最後に「アプリを更新」**して、設定反映の完了を確認してください。統合スクリプト自体はアプリ設定の反映を開始しません。次の第4章では、反映済みの案件管理アプリの定義を使います。

**再実行について：** 存在する同一コード・同一型の項目はスキップします。既存テーブルの基本列が不足している場合や型が異なる場合は、安全のため停止します。途中停止後に再実行する場合は、Consoleログとプレビュー設定を確認してください。既存フィールドの削除・変更は行いません。

## 4. 明細管理アプリの作成

1. **案件管理アプリ**を開きます（明細管理アプリではありません）。
2. 第3章のフォーム変更がすべて反映済みであることを確認します。
3. `scripts/create-proposal-detail-app.js` をConsoleで実行します。
4. 作成確認ダイアログで承認します。
5. Consoleに出力された**新しい明細管理アプリID**を記録します。
6. アプリ作成・設定反映の完了を確認し、フィールド構成と権限を確認します。

このスクリプトは案件管理の**反映済み**フィールド定義を参照し、担当者別明細5テーブルの提案商品・確度・商談フェーズの型と選択肢を検査します。作成する明細管理アプリには、案件レコードID、担当者No.、担当者名、提案商品、確度、商談フェーズ、見込み金額、受注金額、受注予定日、受注日、メモ、コピー元明細行IDなどが含まれます。

**注意：** このスクリプトは新規アプリを作成するため、安易に再実行すると別アプリが作成される可能性があります。エラー時は作成途中のアプリIDを先に確認してください。アプリ設定の反映開始後、完了を待つ処理はありません。

## 5. 顧客管理：事業所階層・現場NG項目の追加

1. **顧客管理アプリ**を開きます。
2. `scripts/add-customer-hierarchy-fields.js` をConsoleで実行します。
3. 追加内容を確認し、承認します。
4. フォームに次の5フィールドを配置し、「アプリを更新」します。

| フィールドコード | 内容 |
|---|---|
| `office_id` | 事業所ID |
| `honsha_office_id` | 本社事業所ID |
| `parent_office_id` | 親事業所ID |
| `genba_ng` | 現場NGのチェックボックス |
| `effective_genba_ng` | 現場NG判定 |

提供ZIPのスクリプトは `kintone.app.getId()` を使用して**現在のアプリIDを取得**します。以前の説明にあった「固定アプリIDの修正」は、このZIP版では不要です。既存フィールドがある場合は、コードだけでなく型・設定も確認してください。

## 6. 環境設定JavaScriptを準備する

ここまでで担当者管理と明細管理のアプリIDが確定しています。`src/config/production.js` をひな形に、**適用先のIDへ置き換えた設定ファイル**を準備します。ファイル名は `production.js` のままで構いません。

```javascript
window.SFPACK_CONFIG = Object.freeze({
  contactAppId: 123,        // この環境の担当者管理アプリID
  proposalDetailAppId: 456, // 第4章で作成した明細管理アプリID
});
```

`123`、`456` は説明用の仮値です。**必ず実際のIDに変更してください。** ZIP内の `src/config/production.js` には `946`、`947` が記載されていますが、どちらもコメント上は仮IDです。無変更で使用しないでください。APIトークンや秘密情報は書き込まないでください。

## 7. JavaScriptをkintoneへ登録する

この段階ではじめて、通常のJavaScriptカスタマイズを登録します。

### 7.1 案件管理アプリ

1. 案件管理 → アプリの設定 → **JavaScript / CSSでカスタマイズ**を開きます。
2. **PC用JavaScript**に次の2ファイルを**この順番**で登録します。
   1. 第6章で準備した `production.js`
   2. 開発担当者から配布された `sfpack-customization.js`
3. 同一スクリプトの二重登録がないことを確認します。
4. 設定を保存し、「アプリを更新」します。

`production.js` はアプリIDを先に定義する設定ファイルで、`sfpack-customization.js` は機能本体です。**順番を逆にしないでください。** `src/config/production.js` という表記はリポジトリ内の保管場所であり、kintoneでパス文字列を指定するという意味ではありません。

### 7.2 顧客管理アプリ

1. 顧客管理 → アプリの設定 → **JavaScript / CSSでカスタマイズ**を開きます。
2. PC用JavaScriptに、配布された `customer-customization.js` を登録します。
3. 設定を保存し、「アプリを更新」します。

担当者管理・明細管理アプリには、このリポジトリのカスタマイズJSを直接登録しません。`src/main.js` でCSSをインポートしているため、別途CSSを配布・登録する必要があるかはビルド成果物と実画面で確認してください。開発用の `localhost` / `127.0.0.1` URLを本番環境に登録しないでください。

## 8. 導入後の動作確認

検証用レコードを使用し、ブラウザーのConsoleに想定外のエラーがないかも確認します。

- [ ] 案件管理の新規・編集画面で担当者選択ボタンが表示される
- [ ] 担当者を選択すると担当者テーブルと担当者名が反映される
- [ ] コピー元の `明細テーブル` に7列が表示される
- [ ] 共通明細から担当者別明細へコピーできる
- [ ] 既存入力済み明細を意図せず上書きしない
- [ ] 明細管理アプリへ明細を登録・更新できる
- [ ] コピー履歴フィールドが想定どおり更新される
- [ ] 顧客管理の事業所階層・現場NG判定が動作する
- [ ] 一般利用者の権限で必要な操作ができる

権限エラー時は、案件管理・担当者管理・明細管理・顧客管理のレコード閲覧／追加／編集権限を確認してください。

## 9. 既存環境の更新・切り戻し

**必要なフォーム・スペース・参照先アプリがすでに存在する環境**では、第3～5章の初期追加スクリプトを再実行せず、まず現在のスキーマと新しいJSの要求を照合してください。

更新時は現行のJavaScriptと設定ファイルを保管し、第6～8章の手順で入れ替え・確認します。問題があれば旧JSに戻してアプリを更新します。ただし、**JSの切り戻しでは、変更済みレコードや追加済みフィールドは元に戻りません。**
