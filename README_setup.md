# kintone SFA Pack Customization — 導入・設定手順

本書は、**ビルド済みJavaScriptをkintoneへ適用する導入担当者・アプリ管理者向け**の手順書です。Node.js、pnpm、Vite、VS Code等の開発環境は不要です。機能仕様は [README.md](README.md)、ソースの変更・ビルド方法は [README_dev.md](README_dev.md) を参照してください。

> **適用前の注意**：本プロジェクトはPoCを起点としています。既存データを持つ運用アプリへの初期導入では、事前に検証環境での確認、バックアップ、権限確認、変更計画の承認を行ってください。以下のアプリIDは環境ごとに異なります。

## 1. 導入パターン

| 作業 | 既存環境のJavaScript更新 | 新規環境への初期導入 |
|---|---|---|
| アプリ・フィールド・スペースの準備 | 原則不要（変更がない場合） | 必要 |
| 環境別設定 `production.js` の確認 | 必要 | 必要 |
| ビルド済みJavaScriptの登録 | 必要 | 必要 |
| 権限確認・動作確認 | 必要 | 必要 |

**すでに必要なアプリ・フィールド・スペースが存在する環境で、JavaScriptだけを更新する場合**は「2. 準備」「3. JavaScript適用」「4. 動作確認」「5. 更新・切り戻し」を実施してください。新規環境は「6. 初期セットアップ」も先に実施します。

## 2. 準備・事前確認

### 2.1 適用対象と成果物

| kintoneアプリ | 適用ファイル | 備考 |
|---|---|---|
| 案件管理 | `src/config/production.js` → `dist-prod/sfpack-customization.js` | **この順番**でJavaScriptを登録する |
| 顧客管理 | `dist-prod/customer-customization.js` | 顧客管理側のバンドル |
| 担当者管理 | 直接のカスタマイズ登録対象ではない | 案件管理から参照する |
| 明細管理 | 直接のカスタマイズ登録対象ではない | 案件管理からレコードを登録・更新する |

`dist-prod/` は運用向けに圧縮されたビルド成果物です。`.map` ファイルの登録は不要です。**この2つのバンドルだけでは、必要なフォーム構成やアプリID設定までは作成されません。**

配布された成果物がない場合は、開発担当者に `pnpm run build:prod` で生成したファイルを依頼してください。導入担当者自身がビルドする必要はありません。

### 2.2 アプリIDと環境別設定

案件管理で先に読み込む `production.js` は、適用先の実際のアプリIDを設定したものを使用します。設定例：

```javascript
window.SFPACK_CONFIG = Object.freeze({
  contactAppId: 946,          // 適用先の担当者管理アプリIDに変更
  proposalDetailAppId: null, // 適用先の明細管理アプリIDに変更
});
```

- `contactAppId`：担当者管理アプリのID。
- `proposalDetailAppId`：明細管理アプリのID。**明細レコード化機能を利用する場合は `null` のままにしないでください。**
- 上記 `946` は既存の設定例であり、すべての環境で使える値ではありません。
- `production.js` にAPIトークンや秘密情報を記載しないでください。
- `staging.js` と `production.js` を取り違えないようにしてください。

### 2.3 変更前のチェック

- [ ] 対象kintone環境・アプリ名・アプリIDを確認した
- [ ] アプリ管理権限と、動作確認に使うユーザー権限を確認した
- [ ] 現在登録されているJavaScript・CSS、アプリ設定を控えた／バックアップした
- [ ] 配布ファイルのバージョン・取得元を記録した
- [ ] 必要なフィールド・スペース・コピー先アプリが存在する（新規環境の場合は第6章へ）
- [ ] `production.js` の参照先アプリIDが正しい

## 3. JavaScriptをkintoneへ適用する

### 3.1 案件管理アプリ

1. 案件管理アプリの「アプリの設定」を開きます。
2. 「JavaScript / CSSでカスタマイズ」の設定画面を開きます。
3. **PC用のJavaScriptファイル**に、適用先の `production.js` を登録します。
4. その**後ろ**に `dist-prod/sfpack-customization.js` を登録します。
5. 既存の同一カスタマイズがあれば二重登録しないよう、旧ファイルとの入れ替えを確認します。他のカスタマイズやプラグインとの読み込み順も確認します。
6. 必要な独自CSSが別途配布されている場合は、その適用方法を開発担当者に確認します（本書ではCSSの配布有無を確定していません）。
7. 設定を保存し、**「アプリを更新」**して反映します。

登録順序：

```text
[1] production.js
[2] sfpack-customization.js
```

### 3.2 顧客管理アプリ

1. 顧客管理アプリの「アプリの設定」→「JavaScript / CSSでカスタマイズ」を開きます。
2. **PC用のJavaScriptファイル**に `dist-prod/customer-customization.js` を登録します。
3. 旧バージョンとの二重登録がないことを確認します。
4. 設定を保存し、**「アプリを更新」**して反映します。

> 本番環境に `https://127.0.0.1:5500/` や `localhost` の開発用URLを登録しないでください。配布済みのJSファイルをアップロードするか、組織で管理する正式な配信先を使用します。

## 4. 適用後の動作確認

まず検証用レコードで確認し、既存の重要データを不用意に変更しないでください。

| 対象 | 確認項目 | 結果 |
|---|---|---|
| 案件管理 | レコード画面がエラーなく表示される | □ |
| 案件管理 | 担当者選択の操作ができる | □ |
| 案件管理 | 共通明細から担当者別明細へのテーブルコピーができる | □ |
| 案件管理 | 担当者別明細のクリア操作が想定どおり動作する | □ |
| 案件管理 | 「明細レコード化」で明細管理アプリへ登録・更新できる | □ |
| 案件管理 | 再実行時の重複防止・コピー履歴を確認できる | □ |
| 顧客管理 | 事業所階層と現場NGの連鎖更新・再同期が動作する | □ |
| 共通 | 一般利用者の権限でも必要な操作ができる | □ |
| 共通 | ブラウザーの開発者ツール Console に想定外のエラーがない | □ |

**権限上の注意**：明細レコード化では、コピー先の閲覧・追加・編集権限と、コピー元の編集権限を確認してください。API実行時には利用ユーザーの権限が適用されます。

## 5. JavaScript更新・切り戻し

### 更新

1. 更新対象のアプリ・配布バージョン・作業日時を記録します。
2. 現行のJavaScript、環境別設定、必要に応じてアプリ設定を保管します。
3. 第3章の手順で**旧バンドルを新バンドルへ置き換え**ます。`production.js` の設定値も再確認します。
4. 「アプリを更新」後、第4章の動作確認を実施します。

### 問題発生時の切り戻し

1. 対象アプリで登録した新しいJavaScriptを、保管した旧バージョンに戻します。
2. 必要に応じて旧 `production.js` とCSS設定も戻します。
3. 「アプリを更新」して反映し、主要機能を再確認します。
4. **JavaScriptの差し戻しだけでは、実行中に追加・更新したレコードや変更したフォーム設定は元に戻りません。** データ・スキーマの復旧は別途判断してください。

## 6. 新規環境への初期セットアップ（初回のみ）

この章は**新規にSFAパックのアプリを準備する場合**の概要です。既存環境へのJS更新だけなら不要です。スクリプトはJavaScriptカスタマイズとして登録するものではなく、**対象アプリ画面のブラウザー開発者ツール Console で、管理者が内容を確認して実行するセットアップ用コード**です。

### 6.1 対象アプリを準備する

案件管理、顧客管理、担当者管理、および必要に応じて活動履歴アプリを用意します。明細レコード化機能を使う場合は明細管理アプリも必要です。各アプリのルックアップ・関連設定・権限は環境に応じて確認してください。

### 6.2 案件管理の基本フィールド・スペース

` scripts/add-deal-proposal-fields.js `（リポジトリの実ファイル名を確認）で、担当者テーブル、共通明細テーブル、担当者別明細5テーブル、担当者紐付け用の管理フィールドを追加します。**初期状態のアプリに対応した修正版**を使用してください。旧版は一部テーブルの存在を前提とするため、適用しないでください。

フォーム編集画面で、次のスペースを手動配置します。

| スペースの要素ID | 用途 |
|---|---|
| `selPerson` | 担当者選択ボタン |
| `copyProposalDetails` | テーブルコピー等のボタン |

加えて、明細レコード化のコピー履歴フィールド `最終明細コピー日時`（日時）と `最終明細コピー実行者`（ユーザー選択）を用意します。**「明細レコード化」ボタンを配置するスペースの要素IDも、適用する版の `src/config/fields.js` にある `DEAL_FIELDS.PROPOSAL_COPY_SPACE` の実値と一致させてください。** 現時点で参照した資料だけではその実値を確定できないため、導入前に開発担当者へ確認してください。

### 6.3 明細テーブルの金額・日付フィールド

`add-proposal-financial-fields-post.js` を案件管理アプリのConsoleで実行します。`明細テーブル` と `担当者別明細01`～`担当者別明細05` の計6テーブルに、各4フィールド（`見込み金額`、`受注金額`、`受注予定日`、`受注日`）を追加するスクリプトです。既存フィールドは型を確認してスキップしますが、途中エラー時はログと追加済みフィールドを確認してください。

**フォームを確認し「アプリを更新」した後**、次の明細管理アプリ作成へ進んでください。スクリプトはアプリ更新を自動実行しません。

### 6.4 明細管理アプリの作成

`create-proposal-detail-app.js` を案件管理アプリのConsoleで実行します。案件管理の**反映済み**フィールド定義を参照して、新しい「明細管理アプリ」を作成するスクリプトです。

- 実行前に、担当者別明細5テーブルのフィールド定義・選択肢が揃っていることを確認します。
- スクリプトは新しいアプリを作成し、フィールドを追加してデプロイを開始します。**完了まで待機する処理はない**ため、アプリの更新状態・フォーム・アクセス権を確認します。
- **再実行すると別のアプリが作成される可能性があります。** エラーが発生しても安易に再実行せず、ログに表示された新規アプリIDと作成状況を確認します。
- 作成された明細管理アプリIDを `production.js` の `proposalDetailAppId` に設定します。

### 6.5 顧客管理の階層・現場NGフィールド

`add-customer-hierarchy-fields.js` で次の5フィールドを追加します。

| フィールドコード | 用途 |
|---|---|
| `office_id` | 事業所ID（重複禁止） |
| `honsha_office_id` | 本社事業所ID |
| `parent_office_id` | 親事業所ID |
| `genba_ng` | 現場NG設定（チェックボックス） |
| `effective_genba_ng` | 現場NG判定 |

このスクリプトには**アプリIDを固定指定した版**があるため、実行前に対象アプリIDを確認し、必要に応じて `kintone.app.getId()` を使うよう修正します。追加したフィールドはフォームに手動配置し、「アプリを更新」してください。

### 6.6 セットアップ用スクリプト共通の実行方法

1. 検証環境で対象アプリを開き、アプリIDと管理権限を確認します。
2. スクリプトの全文と対象アプリ、既存フィールドの有無を確認します。
3. ブラウザーの開発者ツール（F12）のConsoleで実行します。
4. 確認ダイアログ・ログ・エラー内容を確認します。
5. アプリ設定のフォーム・レイアウトを確認し、必要な手動配置を行います。
6. 「アプリを更新」して設定を反映します（ただし明細管理アプリ作成スクリプトはデプロイ開始処理を含みます）。
7. 第2～4章に戻り、環境別設定とJavaScriptを適用して機能確認します。

> 初期セットアップスクリプトの詳細な仕様・注意点は [README_dev.md](README_dev.md) と各スクリプトの実装を優先して確認してください。スクリプトが既存アプリの状態に適合することを確認するまでは実行しないでください。
